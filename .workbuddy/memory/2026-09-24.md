## 2026-09-24 校园 CAS 登录报 CAMPUS_ACCOUNT_NOT_FOUND 排查

- 现象：https://gordanshop.com/admin/login 输学校账号密码后返回 401 `{"errorCode":"CAMPUS_ACCOUNT_NOT_FOUND","message":"校园账号未关联平台用户","path":"/api/security"}`
- 结论：**不是密码错，CAS 认证已通过**。失败点在 `CampusIdentityService.resolve()`（src/main/java/.../auth/campus/service/CampusIdentityService.java:50-51）
- 根因（已实测）：本机容器 `ai-gateway-postgres` 的 `ai_gateway` 库中 `sldd_system_users` **0 行**（`ai_enterprise` / `ai_api_key` / `campus_identity_binding` / `ai_user_free_quota` 同样为 0）。该表是算力平台用户表的**只读镜像**，需平台侧同步；standalone 部署下为空 → 任何 CAS 账号都匹配不到 → 必然 401。代码设计上明确"不自动创建平台用户"
- 登录链路：/admin/login 只有 CAS 按钮 → 302 `cas.ntit.edu.cn/cas/login?service=https://gordanshop.com/api/auth/cas/callback?state=...` → 回调 `CasProtocolClient.validate()` 成功 → `resolve()` 用 CAS `localAccount`（缺省 `account`）查 `sldd_system_users.user_id`
- 干扰项：响应里的 `"path":"/api/security"` 是 `SecurityExceptionHandler.getCurrentPath()` 硬编码兜底字符串（:131-135），不是真实请求路径
- 第二道坎：`CAMPUS_ADMIN_ACCOUNTS`（.env）当前为空 → CAS 登录只给 `USER` 角色；而 `/api/admin/**`、`/api/security/**`、`/api/config/**` 要求 `ADMIN`（SecurityConfiguration.java:146-148）。不加白名单则登录成功也进不了管理后台
- 实名校验口径：`RealNameAuthUtils.isRealNameAuthenticated(userType, verifyStatus)` 仅 `(1,4)` 企业已实名 或 `(2,2)` 个人已实名 通过
- 应急通道：`/login/emergency` 页面 → `POST /api/auth/jwt/login`；但 `EMERGENCY_LOGIN_ENABLED=false` 且 `EMERGENCY_LOGIN_ALLOWED_CIDRS=127.0.0.1/32,::1/128`，公网访问会 `EMERGENCY_LOGIN_IP_DENIED`
- 关键表清单：sldd_system_users / sldd_system_user_company / ai_enterprise / ai_api_key / ai_user_free_quota / campus_identity_binding
- 用户选择「先不改，只出报告」：未改动任何数据与配置，产出报告 `docs/zh/troubleshooting/campus-cas-login-not-found.md`
- 待办建议：① 启动自检增加"平台用户表非空"校验（可扩展 CampusAuthStartupValidator）② SecurityExceptionHandler.getCurrentPath() 应真实取 ServerWebExchange 路径 ③ CAS 回调失败时前端应重定向回登录页而非裸 JSON

## 2026-09-24 gordanshop.com 部署拓扑确认（重要）

- **gordanshop.com 就是本机 Docker 里跑的服务**，不是公网/校园服务器。gordanshop.com 只是 Cloudflare Tunnel 暴露出来的门面
- 完整链路：浏览器 → Cloudflare 边缘（DNS 解析到 104.21.60.190 / 172.67.200.60 / 2606:4700:3031::6815:3cbe）→ Cloudflare Tunnel（容器 `ai-gateway-standalone-cloudflared-1`，4 条 QUIC 出站长连接到 lax08/lax01/sjc01）→ 容器 `ai-gateway-standalone-tunnel-proxy-1`（Caddy，监听 :8081）→ 容器 `ai-gateway-standalone`（alias `gateway`，:8080）
- 隧道为 Cloudflare 侧远程管理，非本地 config.yml。当前 ingress 配置（日志 version=1）：
  `{"ingress":[{"hostname":"gordanshop.com","service":"http://tunnel-proxy:8081"},{"service":"http_status:404"}]}`
- 编排文件：`docker-compose.yml` + `docker-compose.tunnel.yml`；隧道凭据 `.cloudflare-tunnel-token`
- Caddy 配置 `deploy/caddy/Caddyfile.tunnel`：`reverse_proxy gateway:8080`，并把 `/actuator`、`/swagger-ui`、`/v3/api-docs`、`/internal` 一律 404
- 同一容器另映射宿主机 `127.0.0.1:38008` → 8080，所以 `http://localhost:38008/admin/login` 与公网域名是**同一个服务**（实测 Last-Modified 与 Content-Length 完全一致）
- 排查含义：容器一停 gordanshop.com 立刻不可用；本机数据库为空 = 公网登录失败，无需去学校或云侧找原因
