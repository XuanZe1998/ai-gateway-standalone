# 校园账户 Key 上线切换

## 切换前通知调用方

本版本部署后，**所有旧网关本地 Key 立即无法通过认证**。旧配置只读保留作审计，不迁移明文，也不能再从旧接口创建、导入、轮换或启用。外部算力平台 `ai_api_key` 签发的 Key 继续使用原认证路径，不受旧网关 Key 切换影响。新 Key 以 `gw2_` 开头，仅在创建或轮换时返回一次明文。

在部署前通知所有使用旧网关本地 Key 的应用负责人：
1. 提前准备 CAS 校园登录、实名认证以及真实付费账户或月度免费额度。
2. 安排切换窗口，部署后进入「我的工作台 → 我的 Key」新建 Key，安全地更新客户端配置；旧 Key 在切换瞬间就会失败，不能通过旧 Key 拉取新 Key。
3. 调用示例与模型 ID 以「模型与接入」为准。调用结果、Token 和费用在「我的用量」中核对；企业余额是共享余额。
4. 应用负责人在切换后执行真实请求测试并观察 401、403、402、请求成功率和账单归属。

## 部署与验证

- 先备份数据库和配置，执行 PostgreSQL Flyway `V12__campus_gateway_keys.sql`，确认 `campus_gateway_key`、`campus_gateway_key_limit` 创建成功且默认上限行 `(owner_id=0,max_keys=5)` 存在。不要修改或删除外部算力平台的 `ai_api_key`。
- `CAMPUS_DEFAULT_ADMIN=true` 是明确的现阶段全员全局管理员策略。个人入口仅是便捷视图，**不是用户之间的权限隔离**；用户可通过全局管理员入口修改或绕过上限。务必在上线说明中向使用方讲清这一点。
- `CAMPUS_UNRESTRICTED_ACCESS=false`：不再跳过实名与余额校验。未实名用户能查看工作台、创建 Key，但调用会被拒绝；余额和免费额度不足也会被真实拦截。
- 在测试账户上依次验证登录、创建 Key、保存明文、调用、用量和余额更新、停用、启用、轮换（旧值失效）、撤销（不可恢复且释放名额）；检查外部平台 Key 仍可调用，并确认旧本地 Key 返回认证失败。
- Key 数量按未撤销的 Key 计算，包括停用状态。限制和创建在 PostgreSQL 行锁事务中串行化；管理端发放可以绕过限额；可查询生效上限、设定个人覆盖或移除覆盖以恢复全局默认。

## 应急回滚

1. 首选：保持新版本，暂停发布新 Key，修复平台账户绑定、数据库连接或模型配置；不要临时打开 `CAMPUS_UNRESTRICTED_ACCESS`，否则将产生未经校验的上游费用。
2. 若必须回退代码，先回滚应用镜像到切换前版本，并评估旧网关 Key 会被旧代码**重新接受**的安全与成本风险；通知应用负责人切回旧凭据。数据库 V12 表暂时保留，不做破坏性回滚；新 `gw2_` Key 无法被旧代码识别。
3. 恢复新版本时再次通知凭据切换窗口，核对用户归属和账单。不要通过旧配置导入或手工复制新 Key 明文。
